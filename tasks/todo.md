# 描画をビューポート基準に作り替える

## 要求

絵文字を大きく拡大すると表示がドット状に粗くなる。改善したい。

- [x] 公開

## レビュー

### 分かったこと：原因は 2 つあった

**1. 表示用キャンバスの解像度上限（修正した）**

キャンバスが画像全体ぶんを保持していたため、総ピクセル数の上限（400 万）に達すると
それ以上解像度を上げられなかった。

| ズーム | キャンバス | 表示サイズ | 解像度比 |
| --- | --- | --- | ---: |
| 全体表示 | 799×600 | 799×600 | 1.00 |
| 243% | 1782×1337 | 1782×1337 | 1.00 |
| 379% | 2309×1732 | 2779×2085 | **0.83** |

dpr 3 の iPhone では実効 0.28 まで落ちる。

**2. 絵文字フォントの制約（修正できない）**

Apple Color Emoji は **sbix（ビットマップ）フォント**で、グリフの実体は 160px 程度の画像。
拡大するとその画像が引き伸ばされるので、解像度をいくら上げてもドットが見える。
テキストはベクター（アウトライン）なので、この制約を受けない。

**実測での確認**: 同じ 800% 拡大で、テキスト「あA」の輪郭は完全に滑らか。
絵文字はドットが見える。書き出し（原寸 4000×3000）でも同様で、これはフォント側の限界。

### 対処

表示用キャンバスを**画面サイズ固定**にし、見えている範囲だけを描くようにした。

- 描画時に平行移動と拡大を transform で与え、以降は画像ピクセル座標のまま描く
- キャンバスの画素数が拡大率に依存しないので、**どれだけ拡大しても等倍の解像度**で描ける
- メモリと描画量も倍率に依存しない
- 絵文字・文字は変換が掛かった状態で `fillText` するため、拡大しても解像度なりに描かれる
  （テキストは鮮明。絵文字はフォント側の制約が残る）

あわせて必要だった調整:

- ぼかしの作業バッファを `ctx.getTransform()` から得た**実際の描画スケール**基準にした。
  画像座標だけで決めると、拡大時にぼかしだけ粗くなる
- `renderScene` から `scale` 引数を外し、クリアと transform を呼び出し側の責任にした
- 透過を示す市松模様は削除した（キャンバスが画面固定になり、画像の範囲にだけ敷けなくなったため）。
  透過部分は背景色で表示される

### 検証

| 項目 | 結果 |
| --- | --- |
| テキストの 800% 拡大 | 輪郭が完全に滑らか（ドットなし） |
| 書き出し | 原寸 900×600、マスク内のディテールが外側の 1/6（正しく適用） |
| 性能（WebKit・4000×3000） | ボカシ 11.9ms / モザイク 11.6ms / 柔らかさ込み 11.5ms（いずれも rAF 上限） |
| WebKit のボカシ・柔らかさ | 目視で正常 |

24.75KB → **24.71KB**（市松模様の CSS を削ったぶん微減）。上限 25KB。
