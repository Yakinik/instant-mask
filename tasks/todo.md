# 描画の高速化と下部エリアのレイアウト刷新

## 要求

1. iPhone で操作がカクつく。高速化したい
2. 下部機能エリアの並びが表示バリエーションごとにガチャつく。安心できる並びを定義して整える
3. 「画像を保存」を PC とモバイルで分ける（モバイル＝カメラロール、PC＝ダウンロード）
4. 絵文字・文字を選択中のとき
   - 「内容を変更」はモーダル名を「内容を変更」にし、設定済みの文言を入力欄に反映する
   - 「+ 絵文字・文字」は編集ではなく追加として振る舞う

## レビュー

### 1. 高速化

**計測（WebKit・4000×3000 の画像・レイヤをドラッグ）**

| 効果 | 修正前 | 修正後 |
| --- | ---: | ---: |
| ボカシ | 20.0 ms（50fps） | **11.6 ms（86fps）** |
| モザイク | 11.7 ms | 11.7 ms |
| ボカシ + 柔らかさ | 19.9 ms | **11.6 ms** |

11.6ms は計測に使った rAF の間隔そのもので、**描画が 1 フレームに収まっている**状態。

原因はぼかしの計算ではなく、**元画像（4000×3000）から毎フレーム縮小し直していたこと**だった。
対処は 3 つ。

1. **縮小済みソースのキャッシュ** — 描画サイズごとに一度だけ縮小して使い回す。
   レイヤのドラッグ中はサイズが変わらないので縮小が 1 回で済む。
   原寸描画（書き出し）では縮小の意味がないので元画像をそのまま使う。
2. **キャンバス解像度の絶対上限**（総 400 万ピクセル）— 従来は `原寸 × DPR` が上限で、
   4000×3000 を拡大すると 8000×6000（約 192MB）まで膨らむ計算だった。
3. **描画の rAF スロットリング** — ポインタ移動のたびの同期描画を 1 フレーム 1 回に間引く。

### 2. レイアウト

役割ごとに 3 ゾーンへ固定した。

```
[ 内容の設定 ] [ 選択中への操作 ] [ 常時のアクション ]
```

- 未選択とマスク選択で**同じコンポーネント**（`MaskSettings`）を使う。
  従来は別実装だったため項目の有無や順序がずれていた
- 絵文字・文字は `StampSettings`（内容を変更 → スタイル → 大きさ）で同じ位置に置く
- レイヤ操作は選択時だけ現れるが、**未選択でも場所を確保**する。
  畳むと設定ゾーンの幅が変わり、折り返し位置＝行数が動いてしまうため
- スライダーは幅を固定した。伸縮させると余白の差で長さが状態ごとに変わる
- 狭幅では flex-wrap 任せをやめ、ゾーン単位で行を分ける（区切り線つき）
- ツールバーにあったヒントはステージ下部へ移した（レイヤが 0 個のときだけ表示）

**検証**: デスクトップで未選択・選択中を切り替えても、スライダー位置（14-204）と
共通アクションの位置（全消去 x=921）が**完全に一致**することを実測で確認。

### 3. レイヤ ID の衝突（検証中に発見した不具合）

ID はモジュールスコープの連番だが、**リロードでカウンタが 0 に戻る一方、IndexedDB から
復元したレイヤは前回の ID を持ったまま**なので、復元後に作ったレイヤと衝突していた。
実際に 3 つのレイヤがすべて `l1` になり、選択が別のレイヤに解決されていた。
復元時に採番を進める `reserveLayerIds()` を追加して解消（`l1` / `l2` で一意になることを確認）。

### 4. 保存の表記

動作自体は以前から環境で分岐していた（モバイル＝共有シート、PC＝ダウンロード）が、
表記が共通で違いが見えなかったため、モバイルでは「写真に保存」と出すようにした。
「カメラロールへ保存」は狭幅で幅を取りすぎるため、意味が同じで短い表記を選んだ。

### 5. ピッカーの追加 / 編集

`emojiPickerMode` を持たせ、開いた経路で振る舞いを変える。

| 経路 | モーダル名 | 入力欄 | ボタン | 動作 |
| --- | --- | --- | --- | --- |
| 「内容を変更」 | 内容を変更 | 現在の文言 | 変更 | 差し替え |
| 「+ 絵文字・文字」 | 絵文字・文字を追加 | 空 | 追加 | 新規追加（選択中でも） |

検証: 選択中に「+ 絵文字・文字」から追加してレイヤが 3 → 4 に増えること、
「内容を変更」では入力欄に「社外秘」が入ることを確認。
